## Learning Philosophy

### Primary goal: engineering understanding

This is a **learning course** — build real understanding you can apply when designing and shipping systems. Do not frame lessons around interview answers or employer expectations.

Do **not** excessively focus on mathematics.

For mathematical concepts:

1. Explain the intuition
2. Show the important equation if useful
3. Explain what the variables mean
4. Explain why the equation matters to an engineer
5. Move on

### For every concept, prioritize

- What is it?
- Why does it exist?
- How does it work?
- When do I use it?
- When should I **not** use it?
- Tradeoffs, architecture, cost, latency, reliability, security, evaluation
- How the concept applies in production system design

### Teaching layers

| Level | Focus |
|-------|--------|
| 1 — Intuition | Simple explanation |
| 2 — Technical | How it actually works |
| 3 — Engineering | Design decisions and tradeoffs |
| 4 — Production | Real enterprise architecture |
| 5 — Practice | Apply concepts through exercises and design problems |

## How to Use This Course

| File | Purpose |
|------|---------|
| `COURSE_PLAN.md` | Living 12-week roadmap |
| `PROGRESS.md` | Per-day status, quiz scores, weak areas |
| `INTERVIEW_MASTER.md` | Personal learning reference and concept notes (legacy filename) |
| `week-XX/day-XX.md` | Daily lessons |
| `projects/` | Six incremental projects |
| `notes/` | Personal notes |

### Daily workflow

1. Read the lesson (or generate it when you reach a new day)
2. Complete **Hands-On** and **Design** exercises
3. **Self Assessment** without looking at the lesson
4. Say **"Quiz me on Day X"** for interactive grading
5. Update `PROGRESS.md` and your notes

### Interactive quizzing

When you say **"Quiz me"**:

- Questions without answers
- Grades: 🟢 Solid understanding | 🟡 Correct but needs depth | 🔴 Misunderstanding
- Feedback: what you got right, what you missed, deeper explanation, follow-up

### Important rules

1. **Do not mark a day complete** until you demonstrate understanding
2. **Detailed lessons for Days 4+** are generated when you reach that day
3. **Curriculum is flexible** — adjust based on gaps and new technology
4. **Do not fabricate experience** — document hands-on work honestly
5. **Learning over performance** — understand concepts deeply; do not optimize for rehearsed answers
